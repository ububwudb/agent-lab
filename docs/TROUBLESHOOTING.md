# 踩坑记录

> 这份文档记录的是真实遇到的问题和最终怎么解决的。写它的原因很实际：
> 下次再遇到能直接查，也方便别人参考同样的排查思路。

## 一、Agent 循环相关

### 1. 模型反复调用工具，循环停不下来

**现象**：问"沈阳天气"，模型连续调了 6 次 `get_weather`，最后返回"达到最大轮数"。

**定位**：用 `agent_stream_debug.py` 把每一轮 chunk 打出来，发现每次返回的 `tool_calls` 都非空，
且模型在 `content` 里写"我再确认一下"——是提示词让模型以为必须反复验证。

**原因**：① 提示词里写了"必须调用工具获取真实数据"，模型把它理解成"每轮都要调"；
② 循环没有硬上限，理论上可以无限跑。

**解决**：
- 循环加 `MAX_ROUNDS = 6`，并返回明确的最大轮数提示；
- 提示词改成"拿到结果后直接回答，不要重复调用同一个工具"；
- 工具结果里带上数据来源（如"实时天气：晴，17℃"），模型看到有效数据就不再重试。

### 2. 工具调用参数解析失败

**现象**：`json.loads(tc["function"]["arguments"])` 偶发 `JSONDecodeError`。

**原因**：模型生成的 JSON 偶尔带尾部逗号或中文引号，不是严格合法 JSON。

**解决**：包 try/except，解析失败时把"参数不合法"作为观察结果返回给模型，让它下一轮重写。
**不要**直接崩 —— 崩了模型就失去自我修正的机会。

### 3. 模型明明回答了，但代码拿到的 content 是空的

**现象**：Qwen3 系列有时 `content` 为 `None`，答案写在 `reasoning_content` 里。

**解决**：`answer = msg.get("content") or msg.get("reasoning_content") or "（模型没有返回内容）"`。

### 4. 工具报错直接把整条链路搞崩

**现象**：天气接口超时，抛 `requests.Timeout`，整个 Agent 挂掉。

**解决**：所有工具统一约定 —— **返回字符串，不抛异常**。异常也要转成
`f"天气查询异常：{e}（可稍后重试）"` 这种可读文本，让模型自己决定重试还是告知用户。

## 二、外部接口相关

### 5. 和风天气返回 401 / 查不到城市

**原因**：
- 用了 v1 的旧接口路径（`/weather/v1/current/{lat}/{lon}`），新版要用 `/v7/weather/now`；
- `location` 参数的经纬度顺序搞反（正确是 **经度,纬度**）；
- 请求头字段不认 `key`，新版要 `X-QW-Api-Key`。

**解决**：先调 `geo/v2/city/lookup` 拿经纬度，再用 `v7/weather/now`；统一用 `X-QW-Api-Key` 头。

### 6. 接口报 402，整条链路表现为"模型不回话"

**原因**：账户余额不足，`check.py` 里的 402 分支就是为了直接告诉你是钱的问题，而不是网络问题。

**解决**：`.env` 里换后端（智谱 GLM-4-Flash 或本机 Ollama），代码不用改 —— 这也是我把
四项能力都做成"按前缀独立配置"的原因。

## 三、环境相关

### 7. Windows 下中文输出乱码 / conda activate 静默失败

**现象**：控制台中文变问号；`conda activate` 没报错但环境没切过去。

**原因**：conda 在 Windows 默认用 GBK 输出激活脚本，PATH 里含中文路径时会
`UnicodeEncodeError`，而错误被吞掉，表现为静默失败。

**解决**：脚本顶部 `sys.stdout.reconfigure(encoding="utf-8")`；PowerShell profile 里强制
`PYTHONUTF8=1`；运行加 `python -X utf8`。

### 8. 依赖版本冲突（LangChain 1.x 与 0.x API 不兼容）

**现象**：`create_agent` 导入失败 / `checkpointer` 参数不认识。

**解决**：为这个项目单独建 conda 环境，避免和课程用的旧环境混装；代码里对
`checkpointer` 参数做 `try/except TypeError` 降级，保证老版本也能跑。

---

## 四、经验总结

1. **先让循环能跑，再让循环跑对**。一开始就想写完美的提示词，不如先把 `MAX_ROUNDS` 和保护措施加上。
2. **可观测优先**。Agent 出问题时，日志里只有最后一句话是没用的，必须能看到每一轮的 `tool_calls`。
3. **错误是数据**。工具的错误信息写得越具体（状态码、参数、原因），模型自愈的概率越高。
4. **永远准备离线兜底**。演示现场网络不可控，脚本化的假模型能保证"要讲的东西一定跑得出来"。
