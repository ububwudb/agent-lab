# 03 · 多模态 Agent（Gradio 应用）

能听（麦克风）· 会说（语音合成）· 会看（摄像头 / 屏幕）· 会用工具（天气 / 计算 / 笔记 / 打开网页）

从 01、02 的"能跑通"推进到"能给人用"：界面、语音链路、视觉理解、工具注册、一键自检。

## 快速开始

```bash
copy .env.example .env
pip install -r ../requirements.txt

python check.py        # 先自检：六项能力哪一项能通、哪一项挂了、为什么挂
python app.py          # 打开 http://127.0.0.1:7860
```

Windows 下中文乱码可加 `python -X utf8 app.py`。

> 为什么单独写 `check.py`：多模态链路一挂，你根本分不清是 ASR、模型余额、网络还是摄像头权限。
> 六项分开测，错误信息直接说人话（例如 402 会明确提示"余额不足，去换后端"）。

## 架构

```
麦克风 ──► asr.py ──► 文本 ──┐
                            ├──► agent.py（LangChain Agent + 9 个工具 + 多轮记忆）
摄像头 ──► vision.py ───────┘         │
屏幕   ──► vision.py ─────────────────┤
                                      ▼
                              tts.py（edge-tts，免费）──► 扬声器
                                      ▼
                                 app.py（Gradio 三标签页）
```

## 文件

| 文件 | 作用 |
|---|---|
| `config.py` | 配置集中管理，四个能力可各自指向不同后端 |
| `agent.py` | Agent 本体：工具注册 + 多轮记忆（`thread_id`） |
| `tools.py` | 9 个工具：天气 / 计算 / 时间 / 摄像头 / 屏幕 / 打开网页 / 写笔记 / 读笔记 / 列桌面 |
| `asr.py` | 语音 → 文字（SenseVoiceSmall，可换本地 faster-whisper） |
| `tts.py` | 文字 → 语音（edge-tts 免费，或硅基 CosyVoice2） |
| `vision.py` | 摄像头抓帧 + 图片 base64 编码 + 视觉模型问答 |
| `app.py` | Gradio 界面：语音对话 / 摄像头看世界 / 文字对话（调试用） |
| `check.py` | 一键自检六项链路 |

## 可以这样问它

- 「沈阳和北京温差多少度」→ 查两次天气再算减法
- 「帮我看看摄像头里有什么」→ 抓帧 + 视觉模型
- 「我屏幕上现在是什么」→ 截屏 + 视觉分析
- 「帮我记一下明天交实验报告」→ 写进 `notes.md`
- 「我之前记了什么」→ 读笔记
- 「打开哔哩哔哩」→ 调浏览器

## 设计要点

**1. 配置与代码分离。** 四项能力（文本 / 视觉 / 语音识别 / 语音合成）分别用
`LLM_*`、`VL_*`、`ASR_*`、`TTS_*` 前缀独立配置，没配就回落到默认。换平台只改 `.env`，代码一行不动。
这样在"余额不足"和"想用本地 Ollama"之间切换的成本是零。

**2. 工具永远返回字符串。** 包括错误。摄像头被占用时返回的是
`"[摄像头] 打不开摄像头，可能被别的程序占用了，或者索引不对（试试 1）"`，
模型拿到这句话还能继续对话，而不是整个进程崩掉。

**3. 语音链路可降级。** TTS 默认走 edge-tts（免费、不限量），需要更自然的音色才切到付费 API。

**4. 隐私边界。** 摄像头画面、屏幕截图会被编码成 base64 发到模型服务端，这一点在界面上要提示用户；
如果要处理敏感内容，应该换成本地模型（Ollama + Qwen2.5-VL）。

## 已知限制

- `InMemorySaver` 是进程内记忆，重启即丢，多实例不共享（生产要换 Redis / Postgres checkpointer）；
- 一次请求可能串行调好几次模型，首字延迟叠加，长回答体验一般（改进方向：流式输出）；
- 语音识别依赖网络（硅基接口），离线场景需要换 faster-whisper 本地推理。
